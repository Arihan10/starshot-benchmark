# SceneBench — Mesh → Gaussian Splat Delivery Pipeline

> **Status:** Living design doc and agent-context file. Reflects decisions as of the current design pass; meant to be reviewed and iterated. Sections tagged **[OPEN]** are undecided. Sections tagged **[LOCKED]** are settled decisions.
>
> **How to read this:** §1–§4 are shared foundation. **§5 is the pipeline to build first (no lighting).** §6 is what to add later for lighting. §7–§12 are supporting detail (mechanics, caveats, knobs, milestones, tooling, open questions).

---

## 1. Purpose & goal

**SceneBench** is a public, pairwise-voting website (in the spirit of minebench.ai) where users compare 3D scenes generated by different LLMs, to **benchmark LLM spatial reasoning**. Each scene is one LLM's decomposition of a prompt into a parametric 3D environment.

**The problem:** generated scenes are multi-gigabyte meshes and cannot be shipped to a browser for interactive A/B voting.
- Measured example (`runs/.../modern-house/opus-new`): **252 placed objects, ~7.6 GB raw**; individual objects up to ~47 MB. The KTX2/Meshopt-optimized twin is ~116 MB / 173 objects — still too heavy for fast two-up web voting, and it's a per-object mesh set, not a unified renderable.

**The solution:** deliver each scene as a **compressed Gaussian splat** — tens of MB, 60+ fps in a browser, free-fly — produced by **directly converting the existing meshes** (and, later, baking lighting into them).

**Framing:** the splat is a *delivery/presentation* representation that lives **downstream** of the parametric scene. The internal mesh pipeline and the observability/debug platform are unchanged; splats are only for the public voting site.

---

## 2. Locked decisions & constraints  [LOCKED]

- **Free-fly is required.** Voters fly the camera freely *within the scene* — not a fixed orbit. The fly volume is bounded by the **scene AABB** (§3).
- **Direct mesh→splat conversion**, not photogrammetry-from-scratch. Geometry comes from the mesh, so there is **no COLMAP/SfM**, no pose estimation, and correct structure from the start (the largest error source in real-world splats is eliminated).
- **TRELLIS outputs textured PBR GLB meshes**, NOT Gaussians. Its texture stage produces **base color + normal + metallic-roughness** via mesh extraction (`o_voxel.postprocess.to_glb`). The `.ply` entry in the assets API is an archive MIME entry, **not a verified Gaussian export**. Therefore conversion is required; there is **no generator-native-Gaussian shortcut** to rely on. (SLat = "Structured LATents", the model's diffusion latent — not "splat".)
- **Clean albedo assumed** — TRELLIS base color is treated as true de-lit albedo, so there is **no de-lighting pass** and **no double-lighting** risk.
- **Standard lighting = one fixed sky HDRI** (image-based lighting), applied identically to every scene for fairness, plus interior emitters + a neutral interior fill (lighting phase only), at a fixed exposure/tonemap. Lighting is deferred in the first build.
- **Build order:** ship the **entire pipeline WITHOUT lighting first** (including cameras and fine-tune), then add lighting as an additive change.

## 3. Inputs & conventions

- **Unit of work = one cell** = `(run, scene, model)`, on disk under `runs/<run>/<scene>/<model>/`.
- **Meshes (input):**
  - `objects-generated/` — raw world-placed Trellis GLBs.
  - `objects-generated-optimized/` — KTX2/Meshopt twin. **Use this as the sample/render source** (fast to load).
  - Each object is already placed in world space (`rescale_mesh_to_bbox` in `server/app/pipeline/generation.py`).
- **Scene tree (input):** `events.jsonl` — one `bbox` event per node:
  `{"kind":"bbox","id","origin":[x,y,z],"dimensions":[w,h,d],"parent_id","node_kind"}` where `node_kind ∈ {zone, frame, object}`.
  - `frame` = structural shell (ground/floor/walls/ceiling/columns/curbs). A **ceiling/roof frame capping a region ⇒ enclosed region**; ground-only ⇒ open. This is the built-in enclosed-vs-open signal.
- **Materials:** PBR — base color (albedo), normal, metallic-roughness. `server/app/utils/glass.py` flags transparent surfaces; the metalness channel flags reflective ones.
- **Scene AABB (the free-fly play volume):** the axis-aligned box enclosing **all placed geometry**. Usually the `root` zone bbox, but because objects can be placed outside root, compute it as the **per-axis max extent over every placed node**. Derived per scene — **not a tunable knob**.
- **Coordinates:** Y-up, right-handed, meters. Canonical front: +X = right, +Y = up, +Z = toward the viewer.
- **Existing infra to reuse:** GPU workers — **Modal, or a local CUDA box** (the current unlit run targets a colleague's **RTX 3060 / 8 GB**). The Three.js viewer `client/public/js/scene3d.js` (KTX2/Meshopt loaders) is the **product/debug viewer** — its loaders are also reused by the splat viewer's mesh-compare overlay — but **reference renders do NOT use it**: a browser/WebGL stack is impractical on a compute box, so Stage 5 uses a headless GPU rasterizer (**nvdiffrast** — see §5).

## 4. Architecture at a glance

Two branches meet at the fine-tune:

```
                      ┌─────────────────────────── GEOMETRY BRANCH ───────────────────────────┐
Scene source ──────►  composed mesh ──► surfel sampler ──► surfel cloud (albedo) ──────────────┐
(GLBs + events.jsonl)     │                                                                     │
                          │                                                                     ▼
                          └─► free-space voxelize ──► camera planner ──► reference renders ──► FINE-TUNE ──► prune/compress/LOD ──► web viewer
                                (COVERAGE BRANCH)        (poses)         (UNLIT now / lit later)   (splat)      (SOG/.spz + chunks)   (free-fly, streamed)
```

- **Geometry branch** gives correct structure + placement with no cameras.
- **Coverage branch** produces the images the fine-tune trains against.
- **Only the reference-render shading (and an optional bake) depends on lighting.** Everything else is lighting-agnostic — which is why the whole thing can be built unlit and upgraded later.

## 5. Pipeline WITHOUT lighting  — **build this first**

Cameras and the fine-tune are **included**; only lighting is deferred (reference renders are **unlit albedo**). Stage tags: **[reuse]** existing, **[new]** to build, **[integrate]** wrap an off-the-shelf tool.

### Stage 1 — Scene assembler  [reuse]
- **In:** cell's `objects-generated-optimized/*.glb` + `events.jsonl`.
- **Out:** one composed, world-placed mesh in memory + per-object PBR materials + the reconstructed node tree (world AABBs, kinds, parents) + the derived scene AABB.
- Mostly reads existing outputs.

### Stage 2 — Free-space voxelizer + clearance field (the foundation)  [new]
- **In:** composed mesh + scene AABB.
- **Out:** a **reusable dual-resolution grid** (`freespace.npz`): a FINE occupancy grid (accurate near surfaces, for occlusion / thin-gaps) + a COARSE clearance field (distance to nearest surface, for navigation) + a **reachability mask** (free cells in a large enough connected component — exterior + rooms, minus tiny object-interior hollows). Plus a `voxels.bin` viz cloud.
- **Runs FIRST (Option A)** so it's the shared spatial foundation both Stage 3 (surfels) and Stage 4 (cameras) consume — nothing downstream re-voxelizes. Resolution is **adaptive** (fine near surfaces); **reachability** is what separates real navigable free space from a solid's hollow interior (surface voxelization leaves interiors "empty").

### Stage 3 — Surfel sampler (mesh → Gaussians)  [new — core]
- **In:** composed mesh + materials + the **Stage-2 free-space grid**.
- **Out:** a **2DGS surfel cloud** (`cloud.ply`), one **surfel** (flat, surface-aligned 2D Gaussian) per sample:
  - **position** = surface sample point;
  - **orientation** = the surface **normal, flipped toward reachable free space** using the grid (robust to unreliable TRELLIS winding — the grid, not the mesh, decides "outward");
  - **scale** = from **local sample spacing** (so disks tile without gaps/overlap — see §7 "two dials");
  - **color** = **albedo** at that point;
  - **opacity** = the sampled base-color **alpha**, honoring `alphaMode` (see §7 "Opacity init"): **1** for opaque materials (raw TRELLIS), the baked alpha for glass;
  - carry material (metalness/roughness/normal) for later.
  - **format** = a **2DGS `.ply`** (two tangent scales, no thickness axis); a `3dgs` mode appends a thin third scale for 3DGS-only viewers / SOG-SPZ compression.
- **Hidden-face culling:** surfels with no reachable free space on either side (a solid's interior, or the seam between two abutting objects) are dropped — never seen, so wasted budget + floater seeds.
- **Sampling:** area-weighted triangle pick + blue-noise (Poisson-disk) even spacing; **density adaptive to local feature size** (denser on thin/high-curvature geometry — see §8).
- **Reference impls:** `mesh2gaussian`, `Mesh2Splat`; otherwise `trimesh` + `numpy`.

### Stage 4 — Coverage camera planner (free-fly)  [new]
- **In:** the **Stage-2 free-space grid** (reachable candidates + fine-grid occlusion) + the **Stage-3 surfel cloud** (the patch source). Loads **no meshes** and recomputes **no occupancy** — so it can't run off a raw mesh.
- **Out:** **cubemap-native camera poses** (position + the cube faces worth rendering) + the shared render `intrinsics` (90° FOV, resolution, DERIVED footprint budget) + an **occlusion-cull list**.
- **Method:** scatter candidate positions through reachable free space (denser where clearance is small); at each, use a **cubemap** (6× 90° outward views) so orientation isn't a variable; pick positions **greedily (set-cover)** — repeatedly take the one covering the most still-under-covered surface — until every visible patch is seen from ≥ a few angles and ≥ once close enough to meet the **footprint/sharpness budget**; include **near + far** views (multi-scale) with a mip-style train filter.
- **Camera bounds:** positions restricted to reachable free space eroded by a small **collision clearance** (§7). **Free-fly is preserved** — this is a thin safety shell, not a back-off.

### Stage 5 — Reference renders (UNLIT)  [new — cheap; renderer: nvdiffrast]
- **In:** composed mesh (the **de-optimized vanilla GLBs** — geometry + UVs + PNG-transcoded base color, the same source Stages 2–3 read) + camera poses.
- **Out, per camera:** **RGB (albedo, unlit)** + **depth** + **alpha mask**.
- **Renderer — `nvdiffrast` (headless CUDA rasterizer).** Rasterize the triangles from each **pinhole** pose (matching the fine-tune's camera convention), interpolate UVs, and **sample the base-color texture per fragment = albedo** — a flat/unlit shade with **no lighting, no path tracer, no denoiser** (pure rasterization has no Monte-Carlo noise). **Depth** comes from the raster z-buffer, **alpha** from triangle coverage; **honor the base-color alpha for glass** (`BLEND`/`MASK`, per §7) so the references and the splat agree on transparency.
- **Why nvdiffrast (not headless Three.js):** its `RasterizeCudaContext` is **pure CUDA — no browser/WebGL/EGL/display** — so it runs cleanly on a compute box and lives in the **same PyTorch/CUDA process as the gsplat fine-tune** (shared GPU; tensors flow directly, no disk/browser round-trip). A headless Three.js/WebGL renderer would drag a browser stack onto the server for no benefit (voters see the *splat*, not this mesh render). **Trade-offs:** nvdiffrast is a **rasterizer only** — ideal for unlit, but it **cannot do lit GI** (the lit path swaps renderers, §6), and it is **CUDA-only** (runs on the RTX 3060 / Modal, **not** Apple Silicon).
- Depth + alpha are lighting-independent and are emitted here for the fine-tune's losses.
- **Design note:** keep this behind a **pluggable "reference renderer" interface** (`pose → {rgb, depth, alpha}`) so the lit **path-traced** backend (Blender Cycles / Mitsuba, §6) drops in without touching Stages 4/6.

### Stage 6 — Splat fine-tune  [integrate: gsplat 2DGS]
- **In:** surfel cloud (init) + unlit reference renders (+ depth + alpha + exact poses).
- **Out:** an optimized splat — geometrically clean, artifact-free, **flat-shaded**.
- **Losses:** photometric (splat RGB vs unlit reference RGB) + **depth loss (alpha-gated)** for floater suppression. Densification adds Gaussians where rendered error is high; pruning removes redundant ones.
- **SH:** degree-0 (albedo has no view-dependence). Keep SH degree a **config flag** so it can be raised later.
- **Why run this unlit:** the fine-tune's primary job — fixing render-operator errors (silhouettes, thin geometry, zoom detail, alpha-blending artifacts) and floaters — is **lighting-independent**, so it produces a genuinely cleaner splat than raw surfels even with no lighting.

### Stage 7 — Cull / prune / compress / LOD  [integrate]
- **In:** optimized splat.
- **Out:** streamable compressed splat + LOD chunks.
- **Prune** to the free-fly manifold (drop Gaussians with negligible max blending weight across the coverage set → ~2–3× smaller). **Chunk** large scenes spatially and build an **LOD hierarchy** (§7). **Encode** to SOG / `.spz`-class quantization; chunk for streaming.

### Stage 8 — Web viewer  [off-the-shelf]
- **In:** compressed splat + LOD chunks.
- **Out:** a browser view.
- Free-fly camera clamped to the scene AABB; distance-based **LOD streaming** (stream-on-approach). Renderers: Spark, mkkellogg GaussianSplats3D, or PlayCanvas/SuperSplat (WebGPU + WebGL2 fallback).

**Result of §5:** a clean, crisp, **flat-lit** free-fly splat of a real scene, with the entire coverage + fine-tune + compression machinery validated at low cost (unlit renders are cheap).

## 6. Adding lighting later — exact deltas

Reuse the **surfel init (1–2) and the camera plan (3–4) unchanged** (computed once). Adding lighting **re-runs stages 5–7**. The changes:

1. **Stage 5 becomes lit + path-traced.** Swap the reference-renderer backend from **`nvdiffrast` (unlit rasterizer)** to a **path tracer** (Blender Cycles / Mitsuba — a rasterizer can't do GI) under the standard environment (sky HDRI + interior emitters + interior fill), output **HDR RGB** + **denoised** (OIDN/OptiX) + depth + alpha. Depth/alpha logic unchanged (depth loss stays alpha-gated). This is the expensive component; it drops into the pluggable interface from Stage 5.
2. **Optional new step (between 2 and 6): per-surfel lighting bake.** Evaluate path-traced outgoing radiance per surfel under the environment and fit SH — locks in diffuse GI/shadows/color-bleed everywhere, including barely-seen surfaces, as a better init. (May be partly redundant with the image fine-tune — see §12.)
3. **Stage 6 enables view-dependence.** Turn SH degree > 0 **on shiny surfaces only** (metalness flag) so glossy/reflective response is learned; matte stays degree-0.
4. **Lighting rig specifics (§8 caveats):** interior emitters + a standard neutral **interior fill applied to every enclosed region** (so a lamp-less-but-well-laid-out room isn't penalized), and a **decoupled neutral background** for display (don't necessarily show the literal sky; black for space scenes).

**What stays identical:** the sampler, voxelizer, camera planner, cubemap plumbing, depth/alpha, fine-tune harness/losses, cull/compress/LOD, and the viewer.

## 7. Mechanics & clarifications

**Surfel density vs. scale (two dials).**
- *Density* = how many surfels / how closely spaced. *Scale* = how big each disk is.
- Uniform scale over-/under-covers: on sparse regions fixed-small disks leave **gaps**; on dense regions fixed-large disks **overlap/blur**. Fix: **scale ∝ local spacing**.
- *Where detail is needed* comes from two signals: **geometry** (curvature / small triangles → denser, at init) and **rendered error** (the fine-tune's densification adds Gaussians where the render disagrees with the reference — catches *appearance* detail like busy wallpaper on a geometrically-flat wall). Together: geometry seeds shape detail; fine-tune adds appearance detail.

**Bake vs. fine-tune (lighting phase).**
- *Path tracing* = physically simulating light bounces to produce a realistic image (slow, noisy → denoise). *Bake* evaluates it **at surface points** per surfel (no camera) → each blob correct in isolation, everywhere. *Fine-tune* trains the splat **through the real depth-sort+alpha-blend renderer** against reference **images**, fixing errors that only appear when blobs are **combined** (edges, thin geometry, zoom). Bake ≈ 90% instantly; fine-tune polishes the last 10% + view-dependence.

**Supervision data channels** (produced by Stage 5, consumed by Stage 6 losses):
- **Exact poses** (per-render metadata) — render the splat from the identical viewpoint; no SfM error.
- **Depth** (per-pixel) — depth loss; the strongest floater suppressor.
- **Alpha mask** (per-pixel) — don't grow Gaussians in empty space; gate depth loss on transparent pixels.
- **Denoised / fixed-exposure** (qualities of the RGB target) — clean, consistent photometric target. (In the unlit build, denoise is unnecessary.)

**Cubemap** = camera at a point, **6 outward 90° views** (front/back/left/right/up/down) tiling all directions — not photos of a voxel's faces. Makes orientation a non-variable.

**LOD & streaming.** Store multiple detail levels spatially; the client loads **high detail only near the live camera** and keeps far regions coarse, streaming detail **on approach** (like Google Earth). Keeps the **working set** (VRAM + per-frame cost) bounded regardless of total scene size. **LOD applies to every scene**; its *depth* scales with size (shallow for a room, deep for a city).

**Chunked training vs. LOD.** *Chunked training* (partition space, train regions against the views that see them, merge) is a **big-scene-only** necessity, triggered by a size/VRAM threshold — small scenes train whole. The chunks become LOD nodes. LOD-for-delivery is separate and universal.

**Collision clearance** is **small but not 0**: needed for near-plane clipping, voxel-discretization error, and because splats degrade at point-blank range; and it caps how fine you must reconstruct (near-0 ⇒ must reconstruct point-blank detail everywhere ⇒ huge cost). It's a threshold on the clearance field.

**Opacity init (TRELLIS is opaque; `glass.py` bakes the exceptions).** Raw TRELLIS output has **no meaningful opacity** — it's opaque PBR (base color + normal + metallic-roughness); that's precisely why `server/app/utils/glass.py` exists to *synthesize* transparency downstream. During generation, for objects that read as glass (`"window"`/`"glass"` keyword in prompt/noun phrase) **and** were symmetrized (a flat panel), `glass.py` drives white/near-white base-color texels to **alpha `GLASS_ALPHA = 0.065`** and flips the material to **`alphaMode = "BLEND"`** — so the on-disk generated meshes already carry real per-texel alpha for glazing (the `glassify` route forces the same unconditionally). **Init rule (supersedes "opacity = 1 always"):** set each surfel's opacity from the **sampled base-color alpha, honoring `alphaMode`** — `OPAQUE` → **1** (the vast majority, raw TRELLIS), `BLEND`/`MASK` → the **sampled alpha** (glass panes ≈ 0.065, frames ≈ 1). This seeds glass transparency **for free at init** with no hand-flagging; the fine-tune then refines opacity at edges / thin geometry from that correct start. Read `alphaMode` first — only inherit sub-1 alpha where the material is genuinely `BLEND`/`MASK`. (In the unlit build, the Stage-5 reference renderer should honor the same base-color alpha so the reference images and the splat agree on glass.)

## 8. Caveats & fixes (by stage)

- **Stage 2 — thin / high-frequency geometry** (slat fences, foliage, railings — common here) under-sampled at pure area-density → gaps. **Fix:** feature-adaptive density; optional lightweight mesh overlay for hero thin elements.
- **Stage 2 — uniform surfel scale** over/under-covers. **Fix:** scale from local spacing.
- **Stage 2 — hidden faces** waste budget if objects are sampled in isolation. **Fix:** sample the **composed** scene; cull faces invisible from free space (Stage 4 byproduct).
- **Stage 4 — free-fly is the expensive case:** must reconstruct every reachable vantage incl. close-ups; little pruning headroom → larger files. **Fix:** rely on footprint budget + LOD (stream detail on approach) + contribution-pruning; the working set stays bounded even if the total grows.
- **Stage 4 — voxel resolution** too coarse misses thin gaps. **Fix:** adaptive voxels (finer near surfaces).
- **Stage 6 — depth ambiguity on transparent/thin pixels.** **Fix:** alpha-gate the depth loss.
- **Lighting phase — sky HDRI under-lights interiors** (hotel room, office, factory, rooms, Dust2). **Fix:** turn scene light-fixture/emissive objects into emitters + apply a standard neutral interior fill to every enclosed region (regardless of whether the model placed lights).
- **Lighting phase — transparency (glass/water)** is a 3DGS weak spot; refraction + depth are ambiguous. **Fix:** flagged glass/water as thin low-opacity sheets; refraction as a client-side screen-space post-effect.
- **Lighting phase — view-dependent SH inflates size.** **Fix:** SH only on shiny (high-metalness) surfaces.
- **Benchmark fairness under free-fly:** voters can explore A and B differently. **Fix (free-fly-preserving):** synchronize the two A/B viewers' cameras so both are explored from identical vantages.

## 9. Global knobs (uniform across the repository; no per-scene decisions)

1. **Coverage: angles-per-patch** — distinct viewpoints required per surface patch.
2. **Coverage: footprint/sharpness budget** — required on-screen size / closest reconstructed distance.
3. **Size budget** — target Gaussian count / file size (via densification + pruning thresholds).
4. **Collision clearance** — nearest a free-fly camera may approach a surface (couples to #2).
5. **Standard lighting rig** *(lighting phase only)* — the fixed sky HDRI + interior fill level + exposure/tonemap.

Derived (not tuned): the **scene AABB** play volume.

## 10. Build milestones & sequencing

- **M0 — smoke test (optional, ~1–2 days):** Stages 1, 2, 3, encode, 8 only (free-space → raw surfels → view). Answers "does a converted splat of our scenes look acceptable?" No cameras, no fine-tune, no lighting.
- **M1 — full unlit pipeline (the current target):** Stages 1–8 with **unlit** reference renders. Validates the entire coverage + fine-tune + compression machinery cheaply. Output: clean flat-lit free-fly splats.
- **M2 — add lighting:** apply §6 deltas (path-traced references + optional bake + SH-on). Reuses M1's surfel init + camera plan.
- **M3 — SceneBench product:** bake orchestration (Modal, per cell, parallel); serving + pairing + Elo/vote backend; free-fly LOD-streamed frontend with synced A/B cameras + client post-FX (bloom/tonemap/vignette, not baked).

**Dependency shape:** M1 stages are a strict chain (1→2→3→4→5→6→7→8) — free-space (2) feeds both surfels (3) and cameras (4); each stage consumes the previous stage's artifacts (you can't run Stage 4 off a raw mesh). Lighting (M2) touches only Stage 5 shading + optional bake + SH flag.

## 11. Tooling & references

- **Mesh→splat conversion:** `mesh2gaussian`, `Mesh2Splat` (surface splatting from GLB, PBR-aware).
- **Splat trainer (chosen):** **`gsplat` 2DGS** (`rasterization_2dgs` / `simple_trainer_2dgs`) — init from our surfels + alpha-gated depth loss, plus 2DGS's normal-consistency / depth-distortion regularizers. (`splatfacto` / Inria 3DGS remain 3DGS fallbacks.)
- **2D Gaussian Splatting (surfels):** Huang et al., SIGGRAPH 2024 (`hbb1/2d-gaussian-splatting`); Gaussian Surfels.
- **Compression / streaming:** SOG (Spatially Ordered Gaussians, PlayCanvas), SOGS (Self-Organizing Gaussians, Fraunhofer HHI), `.spz` (Niantic), Reduced-3DGS (per-Gaussian SH degree). SH is ~75–81% of a raw Gaussian's data.
- **Web viewers:** mkkellogg GaussianSplats3D (Three.js — our client; **renders 2DGS**), PlayCanvas Engine v2.16+ / SuperSplat (WebGPU, **native 2DGS**), Spark (Three.js, 3DGS). *2DGS SOG/SPZ compression is still landing — see §12.*
- **Reference rendering (unlit):** `nvdiffrast` — headless CUDA rasterizer (`RasterizeCudaContext`; no browser/EGL/display), albedo + depth + coverage, in the same PyTorch/CUDA process as the trainer. **CUDA-only** (RTX 3060 / Modal).
- **Path tracing (lighting phase):** Blender Cycles / Mitsuba / OptiX; denoise OIDN/OptiX.
- **Lighting-into-GS / PBR mesh→GS literature:** CVPR-W 2026 "Efficient Conversion of 3D PBR Meshes to a Relightable Triplane-Based 3DGS for Transmission"; TexGaussian (CVPR 2025); MGM; GBake (reflection probes); GI-GS / GS-IR / Relightable 3D Gaussians; PRTGS. Baking lineage: SNeRG, MERF (browser), BakedSDF.

## 12. Open questions to iterate on  [OPEN]

- **Reference renderer:** **[DECIDED]** unlit → **nvdiffrast** (headless CUDA rasterizer, in-process with the trainer); lit → **Blender Cycles / Mitsuba** (path tracer) behind the same interface. Headless Three.js rejected (browser/WebGL on a compute box, no upside). *Still open:* the exact lit backend, and whether heavy unlit render volume (views × cells) should move to Modal.
- **Splat trainer / representation:** **[DECIDED — unlit] 2DGS via `gsplat`** (`rasterization_2dgs` / `simple_trainer_2dgs`) on the local CUDA box (RTX 3060 / 8 GB) — flat surfel disks, a native fit for our mesh-init surfels and a better match for thin geometry, our exact depth references, and free-fly close-ups. Ecosystem verified sufficient (2026): **training** = gsplat 2DGS (projection depth `D`/`ED`, render-normals, depth-distortion + normal-consistency regularizers, same OpenCV `viewmats`/`Ks` conventions as the 3DGS path); **browser rendering** = PlayCanvas Engine v2.16+ native 2DGS, SuperSplat, and **mkkellogg `GaussianSplats3D` — already our client viewer**. **Locked Stage 4→5→6 contract (unchanged — 2DGS shares it):** **OpenCV** camera convention (+Z forward, +Y down); Stage 5 emits per-view **camera-to-world** in `transforms.json` (`convention: opencv_c2w`) → trainer takes `viewmats = inv(c2w)`; pinhole `K` (`f = R/(2·tan(fov/2))`, `cx=cy=R/2`); **depth = planar camera-space Z in metres** (`render_mode="RGB+ED"`, projection depth — NOT ray distance); **albedo = sRGB 8-bit** compared directly; **SH degree 0** (unlit). Stage-3 surfels are a drop-in init (2DGS `.ply` = ours minus the third scale). Alpha-gated depth L1 kept, plus 2DGS's normal/distortion regularizers for free. **One caveat — compressed streaming:** 2DGS→SOG (`splat-transform`) and SPZ are still landing (SOG support in-progress at PlayCanvas; SPZ/glTF KHR are 3DGS-centric). For M1 (rooms) deliver 2DGS uncompressed/lightly quantized via mkkellogg; if SOG/SPZ is needed sooner, flatten 2DGS→3DGS (`scale_2 = log(1e-6)`) for the compression step only. (Plain **3DGS** remains the fallback if we lose CUDA or need SOG/SPZ immediately.)
- **SH strategy for lighting phase:** degree per surface class; how to detect "shiny enough" from metalness/roughness.
- **LOD & chunking thresholds:** the scene-size cutoff for chunked training; LOD depth policy.
- **Coverage budget defaults:** angles-per-patch and footprint budget starting values; collision clearance value (absolute vs. scaled to scene).
- **Splat format:** `.ply` for M0/M1 → SOG/`.spz` for delivery; which exact encoder.
- **Keep the per-surfel bake?** Given a coverage-complete image fine-tune already injects lighting, the separate hemisphere bake may be redundant — decide in M2.
- **A/B fairness:** whether to hard-synchronize the two viewers' free-fly cameras, or allow independent exploration.
- **Viability bar:** what quality from M0/M1 is "good enough" to justify building M2/M3.
